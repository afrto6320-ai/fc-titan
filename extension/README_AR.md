# CODEX SNIPE 3.5.0 — أحداث اللاعب والشراء الأصلي والعداد

## التثبيت
عطّل الإصدار السابق، وفك ضغط CODEX_SNIPE_v3.5.0.zip، ثم Load unpacked للمجلد الذي يحتوي manifest.json. حدّث صفحة Web App بالكامل.

## أحداث اللاعب
بعد اختيار لاعب، قائمة الحدث تقرأ إصداراته من services.Item.searchConceptItems باستخدام DTO اللعبة الأصلي. لا يعرض الفلتر إلا تقاطع ندرة إصدارات هذا اللاعب مع اختيارات EA المدعومة، بجانب Any. هذه قائمة كتالوج EA وليست دليلًا على وجود عروض حية.
يتم تأكيد Player ID لكل إصدار، مع صفحات محدودة ومهلة زمنية وتخزين مؤقت دقيقتين. إذا غابت الخدمة أو لم تكتمل القائمة يظهر خطأ واضح؛ لا يتم عرض قائمة أحداث عامة باسم اللاعب. عند تغيير اللاعب تُمسح القائمة القديمة، وتُعاد جودة/ندرة البحث إلى Any إذا تغير Player ID لتجنب حدث يخص لاعبًا سابقًا.

## منطق الشراء
1. Start يحفظ جلسة MAIN بقيود السعر والميزانية وعدد المشتريات وهوية اللاعب/الإصدار/الندرة.
2. البحث يستخدم معالج EA الأصلي، ويحفظ مراجع العناصر الحقيقية في الرد الجديد، مرتبطة بـ searchId وTrade ID.
3. عند المطابقة يعاد التحقق من Trade ID وinstance ID وPlayer ID وdefinition ID والندرة والتقييم والسعر، وحدود الجلسة، ورصيد Coins، وcanBuy ووقت المزاد وحالة إتاحة السوق.
4. يتم استدعاء UTItemActionController.bid(item, buyNowPrice)، وهي الدالة التي يستدعيها تأكيد شراء EA، وتستخدم services.Item.bid داخليًا. لا يحتاج هذا المسار ربط الصف بـDOM ولا يقرأ X-UT-SID أو يرسل طلب UTAS مصطنعًا.
5. يضاف المبلغ والشراء للعداد فقط بعد رد ناجح وحالة item.getAuctionData().isWon() من EA.
6. انتهاء العرض يسجل Miss. الرد المجهول أو عدم تأكيد isWon يوقف المسار ولا يعد شراءً ناجحًا. النتيجة غير المؤكدة تمنع بدء جلسة شراء جديدة حتى مراجعة اللعبة وإعادة تحميل الصفحة، لتجنب تكرار محاولة غير محسوبة.
7. Stop يمنع طلبات جديدة. الطلب المرسل فعلًا قد يكتمل؛ إيصال نجاحه يُحسب مرة واحدة حتى لو وصل بعد Stop. لا توجد إعادة محاولة تلقائية لنفس Trade ID الذي أرسلت له محاولة شراء.

## التنبيه عند الخسارة
أزيل تأكيد الشراء العام الخاص بالإضافة. Auto Buy يظل متوقفًا افتراضيًا؛ تفعيله يعني تشغيل المسار ضمن القيود التي أدخلتها.
التأكيد الإضافي يظهر فقط عندما تكون خسارة الشراء التقديرية أكثر من 10%، مع وجود مرجع صالح لنفس النسخة:

`صافي البيع المتوقع = السعر المرجعي × 0.95`
`نسبة الخسارة = (سعر الشراء - صافي البيع المتوقع) ÷ سعر الشراء × 100`

يمكن إدخال سعر البيع المتوقع يدويًا. إذا لم يُدخل، يمكن استخدام getMarketAverage الخاص بنفس عنصر EA عند توفر قيمة موجبة. هذا متوسط مرجعي لا يضمن سعر تنفيذ بيع حي ولا تتوفر له دائمًا معلومات حداثة.
بدون مرجع تظهر «الخسارة غير محسوبة»، ولا يدّعي البرنامج ربحًا أو يضيف تأكيدًا عامًا. حدود السعر والميزانية ورصيد Coins مستمرة. الموافقة على خسارة مرتفعة مربوطة بنفس Trade ID والسعر والمرجع؛ تغيرها يحتاج تحققًا جديدًا.

## العداد
الوقت يعتمد على performance.now، ويظهر HH:MM:SS ويتجمد عند Stop. الحلقة تعرض تقدم الجولة الفعلية، ومرحلة البحث/الشراء/الانتظار، مع الفاصل المختار والعد التنازلي ومدة الجولة المكتملة. هو ليس Ping ولا مؤشر سرعة تخميني. تنتهي الجلسة فور بلوغ حد البحث أو المشتريات بدل انتظار فاصل إضافي بلا داعٍ.

## ما تحققنا منه
اختبارات Node وChromium محلية، بسياقين MAIN/ISOLATED وعقود أصلية مستخرجة من ملفات EA المرفوعة. تشمل شراءً محاكى ناجحًا دون صف DOM، رفض اختلاف السعر والهوية والحدود، انتهاء مزاد، رد نجاح غير مؤكد، Stop أثناء الشراء، إحصاء إيصال واحد، وخسارة أكبر من 10% مقبولة/مرفوضة.
لم تنفذ هذه النسخة شراءً حيًا على حساب EA. الملفات الأصلية وتقارير الحساب وأداة Deep Snipe لا تُضمّن في الحزمة.
