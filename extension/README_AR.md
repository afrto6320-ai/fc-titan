# CODEX SNIPE v3.4.1 — مصدر البيانات والأسماء والصور

## التثبيت
عطّل النسخة السابقة، وفك ضغط CODEX_SNIPE_v3.4.1.zip، ثم Load unpacked للمجلد الذي يحتوي manifest.json. حدّث تبويب EA Web App بالكامل.

## مصادر البيانات بدقة
- بعد الاتصال بوضع EA PAGE FUNCTIONS: خيارات البلد والدوري والنادي والمركز والجودة والندرة/الحدث تأتي من getOptions لعناصر تحكم EA، واختيارها يحدّث فلاتر اللعبة بالـID. هذه قوائم فلاتر، وليست دليلًا على وجود عروض حالية لكل اختيار أو قاعدة شاملة لكل حدث.
- الأسماء تأتي من خيارات EA، أو سجلاتها المرجعية/ترجمتها الأصلية عند غياب اسم الخيار. لا يتم تركيب أسماء أندية وهمية.
- الشعارات والأعلام والأيقونات تأتي من جدول أيقونات EA، مع محاولة ثانية من generateFilterImage الأصلية عند توفر رابط آخر. لا تستخدم مصادر شعارات خارجية.
- إذا لم يصل اسم موثق من EA، يظهر الخيار ضمن مجموعة اختيارية باسم «EA ID … — الاسم غير متاح». يكون مخفيًا افتراضيًا ويمكن إظهاره بالمربع المخصص.
- وجود اسمين متشابهين مع ID مختلف لا يكفي لاعتبارهما تكرارًا. يظهر EA ID، ومعه اسم الدوري عندما توفره بيانات EA. يُحذف تكرار نفس هوية الخيار فقط، وتبقى فهارس EA الأصلية صحيحة عند الاختيار.
- عند تعذر تحميل شعار من المصدر تظهر علامة محايدة، ويعرض الملخص عدد الصور المحملة وغير المتاحة والمعلقة. لا تدّعي النسخة أن كل أصل بصري موجود أو يمكن تحميله.
- قبل الاتصال: كتالوج اللاعبين وصور البطاقات من FUT.GG. بعد الاتصال: بحث اللاعب من محرك EA المحلي الأساسي، وليس جميع نسخ بطاقاته. صور كل نسخ البطاقات ليست مكتملة في الإضافة.
- عروض السوق وIDs والأسعار تُقرأ بعد رد بحث مؤكد. اختيار فلتر لا يعادل العثور على عرض.

## إصلاحات هذه النسخة
- اسم CODEX SNIPE في التبويب واللوحة وChrome وملفات التصدير.
- إزالة تكرار الهوية الأصلية، وعرض EA ID والدوري، والبحث بهما.
- معالجة مفاتيح الترجمة الناقصة بدل عرض global.teamabbr… كاسم نادٍ.
- مصدر الصور الأصلي ومحاولة بديلة أصلية ومؤشر فقد الصورة بدل الأيقونة المكسورة.
- فحص Result list container يصبح «غير مطلوب/غير ظاهر» أثناء فتح شاشة الفلاتر، بدل فشل مضلل.
- تقارير الاتصال والتشخيص تتضمن ملخص آخر قائمة، بعدد المدخلات والتكرارات والأسماء والصور غير المتاحة.

## التحقق
نجحت اختبارات منطق القوائم في Node، واختبار Chromium في MAIN/ISOLATED على صفحة محاكاة. الاختبار شمل تكرار نفس ID، وناديين لهما نفس الاسم وID مختلف، واسم ترجمة مفقود، وفشل الصورة ثم نجاح رابط أصلي بديل، وفشل جميع الروابط دون عرض صورة مكسورة، واختيار ID صحيح بعد إزالة التكرار.
تقارير المستخدم تؤكد نجاح الربط بدوال EA واختيار الفلاتر وتشغيل جولات بحث خالية في v3.4.0. التعديل الجديد v3.4.1 لم يُختبر بعد على حساب EA حي، ولا يضمن إصلاح أصول بصرية غير موجودة على خوادمها.

# CODEX SNIPE v3.4.0 — EA Native Functions

## التثبيت
1. عطّل نسخ CODEX SNIPE الأقدم في chrome://extensions.
2. فك ضغط الحزمة ثم Load unpacked للمجلد الذي يحتوي manifest.json مباشرة.
3. حدّث صفحة EA Web App بالكامل. تحديث الإضافة وحده لا يحمّل سكربت الجسر في التبويب القديم.
4. افتح CODEX SNIPE ثم «اتصل بسوق EA». نجاح المسار الجديد يظهر EA PAGE FUNCTIONS.

## التجربة الأولى
- بعد الاتصال، البحث عن اللاعبين يستخدم محرك اقتراحات EA المحلي، وليس FUT.GG.
- اختر لاعبًا وانتظر تأكيد EA player ID. هذا هو اللاعب الأساسي؛ اختيار نسخة البطاقة يتم من قائمة Event / Rarity الأصلية عند توفرها. لا يعادل اختيار اسم اللاعب اختيار كل إصدار له.
- اختر البلد/الدوري/النادي/المركز/الجودة/الحدث من خيارات عناصر تحكم EA. الخيارات المقفلة من اللعبة تظل مقفلة، والاعتماد بين الدوري والنادي تتولاه EA.
- أدخل Max Buy Now والميزانية ومدى التأخير، واختر عدد بحث صغيرًا مثل 2 للاختبار.
- اترك Auto Buy متوقفًا في التجربة الأولى، ثم Start. العدّاد يزيد بعد رد نتائج جديد مؤكد، بما فيه الرد الخالي.
- Stop يفصل انتظار الرد ويمنع الجولات التالية. الطلب الذي أرسلته EA بالفعل قد يكتمل في اللعبة.

## ما تغير
- سكربت MAIN يتعامل مع Controllers اللعبة، وعميل ISOLATED يربطه بلوحة الإضافة برسائل محددة.
- فتح السوق عبر setGameViewTab وUTMarketSearchFiltersViewController بدل اشتراط بلاطة Transfer Market.
- الأسعار تمر بمعالجات EA وتُقرأ من searchCriteria للتحقق منها، حتى لو حقول DOM تحمل تسميات عامة مثل Any.
- القوائم تأتي من getOptions على عناصر التحكم الأصلية، مع أيقوناتها عند توفرها. لا يتم تركيب قوائم وهمية.
- البحث عبر eSearchSelected: اللعبة تجهز شاشة النتائج وتمسح كاشها المحلي وتنفذ الطلب المعتاد. لا نغير Min Bid عشوائيًا لإدعاء إبطال كاش الخادم.
- وصول onDataChange يثبت وجود رد جديد؛ القراءة تشمل IDs والتقييم وRarity ID والسعر من عناصر بيانات EA المتاحة.
- تغيير فلاتر الاستهداف بعد Start يوقف الجلسة ويطلب تأكيدًا جديدًا.
- تقارير الاتصال تسجل نجاح المسار أو رمز الخطأ، وفحص التوافق يميز ربط الدوال عن فحص DOM.
- تصحيح توقف عداد الوقت عند Stop، ودعم إلغاء البدء الجاري.

## الحدود الحالية
- لم تُختبر النسخة على حساب EA حقيقي. ملفات JavaScript المرفوعة تثبت أسماء الدوال وعقودها في النسخة الملتقطة؛ لا تثبت حالتها في حسابك الآن.
- اختبارات Chromium استخدمت سياقين MAIN/ISOLATED منفصلين فعليًا، مع Runtime/Storage للإضافة محاكيين. لم ينجح تحميل الإضافة نفسها كإضافة مثبتة في Chromium المتاح هنا؛ لذلك هذه الخطوة ضمن تجربة المستخدم.
- إذا تعذر الجسر، يجب تحديث/إعادة تحميل Web App وفحص التقرير. لا يتم التحول خفية إلى أزرار DOM بعد فشل تحقق EA.
- مسار DOM السابق محفوظ للاختبار والتوافق، لكن الحزمة الحالية تستخدم جسر الدوال عند تحميله.
- البحث المتعدد للاعبين ليس مدعومًا بعد؛ القائمة تحفظ أهدافًا، ويُمنع Start عند اختيار أكثر من لاعب.
- صور كل نسخ البطاقات، أسماء كل الأحداث وترجمتها الكاملة، وإعادة تصميم البطاقات لم تُنجز ضمن هذا التعديل. اللوحة تعرض حقول نتائج EA المتاحة وRarity ID.
- Auto Buy ما زال مسارًا تجريبيًا. عند ظهور عرض مطابق، لا ينتقل إلى مسار شراء الواجهة إلا إذا أمكن مطابقة هوية العرض بصف وحيد من DOM؛ وإلا يتوقف دون تأكيد شراء. لم يتم اختبار شراء حقيقي.
- أقل سعر يعني أقل سعر في الرد/الصفحة المقروءة فقط، وليس السوق بالكامل.

## عند الفشل
اضغط «تصدير تقرير الاتصال» وأرسل GPT_SNIPE_Connection.json، ومعه لوج النشاط والصورة التي توضح الحالة. التقرير لا يتضمن كوكيز أو توكنات أو كائن المستخدم أو HTML الصفحة.
